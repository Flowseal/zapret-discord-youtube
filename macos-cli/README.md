# Экспериментальное терминальное меню для macOS

**Возможны баги.** Это экспериментальная реализация, проверенная на одном
Apple Silicon Mac. Нужна проверка в других сетях и на Intel. Гарантий обхода
конкретного провайдера нет; перед использованием ознакомьтесь с ограничениями.

CLI использует нативный utun/BPF движок из macOS-форка и импортирует
`general*.bat`, списки и fake-payload из корня этого репозитория как данные.
BAT-файлы не исполняются. Windows-скрипты не меняются.

## Установка одной командой

Из корня клонированного репозитория:

```sh
sh macos-cli/install.sh
```

Нужны macOS 14+, `/usr/bin/python3` и Xcode Command Line Tools для сборки.
Установщик соберёт universal arm64/x86_64, проверит выбранную стратегию,
запросит обычный sudo и установит launchd-службу. Повторная установка
сохраняет выбранную стратегию и пользовательские списки.

Открыть меню:

```sh
zapret
```

Пункты меню: установка/удаление службы, выбор стратегии, game-filter
off/TCP/UDP/оба с диапазонами, IPSet loaded/any/none и обновление,
управляемый блок hosts, проверка/обновление данных, автообновления, диагностика и dry-run.
Стратегии сортируются естественно: general, ALT, ALT2, ALT3 и далее.

### Обновления данных

Пункт 6: проверить без установки, обновить сейчас, включить/выключить
автообновление. По умолчанию оно выключено. Планировщик launchd проверяет срок
раз в час, а сеть и обновление данных выполняет не чаще раза в сутки; после
ошибки повторяет через час. Неизменившийся IPSet не перезапускает движок.
Удаление службы выгружает планировщик, повторная установка восстанавливает выбор.
Код программы и бинарник движка автоматически не скачиваются.

Без sudo: `zapret check-updates`, статус: `zapret auto-status`.

## Ограничения и безопасность

- Перехватывается исходящий IPv4 обычных пользователей через физический `enN`.
- IPv6, root и неизвестные владельцы сокетов не перехватываются.
- VPN/TUN-маршруты не переводятся напрямую. Наличие default route через enN
  не доказывает прямой путь конкретного адреса: VPN может добавить более
  специфичные префиксы. Другие VPN с туннелированием лучше отключить перед тестом.
- Нужны свободный utun50, Ethernet-совместимый BPF интерфейс и системный PF anchor
  `com.apple/*`. Основной PF ruleset не переписывается.
- Входящие ответы не наблюдаются. autottl/auto-hostlist и преобразования SYNACK
  этой схемой не подтверждены; текущий набор стратегий их не использует.
- Изменения hosts выполняются только отдельным пунктом меню, с резервной копией.
  Удаление службы сохраняет hosts и настройки; свой hosts-блок удаляется отдельно.
- Код устанавливается root-owned; движок сбрасывает root после открытия utun/BPF.
  Настройки проверяются до перезапуска. При отказе активации выполняется откат.
- Watchdog очищает собственный PF anchor после аварии. launchd может восстанавливать
  службу с паузой до примерно 10 секунд, в течение которой возможны обрывы.
- Обновляются только проверенные данные из архива фиксированного upstream commit;
  движок не скачивается и не заменяется обновлением списков.

Программа: `/Library/Application Support/ZapretCLI`. Настройки, списки и журнал:
`/Library/Application Support/ZapretCLI-state`. Собственные домены/исключения
добавляются администратором в `lists/*-user.txt` состояния.

Если команда удалена вместе со службой, сохранённое меню можно открыть так:

```sh
"/Library/Application Support/ZapretCLI/zapret"
```

## Проверка без изменения сети

```sh
sh macos-cli/check.sh
```

Проверка собирает движок и импортирует локальные ресурсы, затем запускает
Python-тесты, dry-run всех стратегий и native harness с заглушками отправки.
Служба, PF, hosts и маршруты этими тестами не изменяются. HTTPS redirect-тест
использует только локальные HTTP/TLS-серверы.

В ходе разработки дополнительно проверены реальные TCP/UDP, HTTP/3, все пункты
меню, удаление/повторная установка и восстановление после аварий. Это ограниченный
набор проверок на одном Mac, а не доказательство отсутствия багов или полной
эквивалентности Windows-перехвату.

Происхождение движка и список локальных изменений: [ENGINE_SOURCE.md](ENGINE_SOURCE.md).


## Если сайт YouTube открывается, а видео не загружается

Проверьте маршрут именно `*.googlevideo.com`: успешная загрузка главной страницы
не проверяет видеопоток. Старые правила стороннего VPN/TUN могут продолжать
отправлять YouTube в VPN даже при работающей службе zapret. Этот CLI не изменяет
настройки стороннего VPN-клиента.

- При проверке без VPN выключите его TUN либо исключите из него YouTube, API
  и медиасерверы вместе: `youtube.com`, `youtu.be`, `googlevideo.com`, `ytimg.com`,
  `ggpht.com`, `youtube-nocookie.com`, `youtubei.googleapis.com`,
  `youtube.googleapis.com`, `youtubeembeddedplayer.googleapis.com`,
  `yt3.googleusercontent.com`, `jnn-pa.googleapis.com` и `youtubekids.com`.
- Страница, API и видео должны выходить через один публичный IP: после смены
  маршрута перезагрузите вкладку, чтобы получить новые подписанные ссылки видео.
- Если сторонний TUN создаёт прямые соединения от root, они исключены из
  перехвата. Для совместной работы нужен прямой выход через физический интерфейс
  от обычного пользователя; одного `direct` в root-процессе недостаточно.
- Не переносите старый запрет UDP/443 без проверки: QUIC и HTTPS/TCP проверяйте
  отдельно. Не отключайте его глобально для остальных сервисов.

На одном Apple Silicon Mac после исправления сторонней маршрутизации проверены
короткий ролик и воспроизведение кадров 3840×2160 длинного ролика. Медиасоединения
TCP и UDP шли через пользовательский прямой relay и zapret без VPN; получено
более 76 МБ медиаданных. Полный просмотр длинного ролика и другие провайдеры
не проверялись. Это результат ограниченной проверки, а не гарантия для любой сети.
